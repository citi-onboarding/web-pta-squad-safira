# ADR-001: Design system of the portal and the manager app

## Context

The web boilerplate ships only Tailwind CSS v4; the manager app boilerplate ships NativeWind with one token file. The prototype is a wireframe and does not define the look. Every screen of the three sprints reuses the same pieces (button, field, select, table, card, status chip, banner, modal, loading, empty and error states), and the portal must meet AA contrast, keyboard navigation and a 390 px layout. The visual identity was approved on 2026-11-26 ("DistriLux — Brand guidelines 1.0").

## Decision

**Portal:** use shadcn/ui as the foundation of the design system, with a light and a dark theme from the start.

- Components are generated by the shadcn CLI into `src/shared/components/ui/` and committed; they become squad-owned code.
- Visual values live only in semantic CSS tokens in `src/shared/styles/globals.css`: light values on `:root`, dark values on `.dark`, exposed to Tailwind with `@theme inline`. Components never use raw colors.
- The theme follows the system preference until the user chooses one with the theme switch; the choice is kept in the browser.
- Features use the components in `src/shared/components/ui/` and do not restyle them.

**Manager app:** keep NativeWind and its single token file (`src/styles/tokens.json`), filled with the same brand values and the Inter font. The app's component choice is left to the MOB tasks.

**Both:** `DESIGN.md` at the root of the web repository is the written standard, and the brand assets come from the approved identity.

Decided by the squad on 2026-11-26.

## Consequences

### Positive

- Accessible behavior (focus, keyboard, ARIA) comes from Radix instead of being written by hand.
- The code lives in the repository, so the squad can give the portal its own look instead of a library's look.
- Tokens with two values make the dark theme and later palette changes a single-file edit.
- Common, documented pattern: easier for the squad and for AI agents to follow.

### Negative

- New dependencies: `clsx`, `tailwind-merge`, `class-variance-authority` and the Radix primitives of each component added.
- Generated code is not updated automatically; upgrades from shadcn are manual.
- Two themes double the contrast work: every token pair must reach AA in both.
- Generated files must follow the repository rules (kebab-case, no barrel files, `src/shared` layer), which needs the `components.json` aliases.

## Alternatives considered

### Own components on Tailwind tokens

No new dependency and full control, but focus handling, keyboard support and ARIA would have to be written and tested by hand for every interactive piece, which does not fit the sprint.

### A packaged component library (e.g. MUI, Chakra)

Fastest start, but it brings its own look and theme system, which competes with Tailwind and makes the squad's own visual identity harder.

### Light theme only

Less work now, but adding a theme later means revisiting every token and component. The squad chose to deliver both themes in this change.
